# The server appends Citations, and a threshold decides whether there are any

Citations are generated by the server from the Chunks retrieval actually returned. The model is never asked to write links, because models invent plausible URLs and a wrong link in a governance answer is worse than no link.

The subtlety worth recording is why a threshold is required at all. Vector search always returns its nearest neighbours, so "nothing relevant" is not a state it can report. Without a threshold, a question about something the wiki has never covered would still receive a footer citing the three least-irrelevant Pages, producing an Answer that looks sourced but is not. When the best Chunk scores below the configured threshold, the Answer is generated from general knowledge, no Citations are appended, and the interface says so explicitly.

## Consequences

- The threshold is the trust-critical parameter of the product. It lives in the environment rather than in code so it can be corrected without a deploy.
- Citations can over-attribute: a footer lists Pages that were retrieved, which is not proof the model used them.
- Because Citations are computed rather than generated, they are deterministic and unit-testable, which is why the LLM call itself is left untested.
- Citation URLs are built by percent-encoding raw GitHub wiki filenames. Filenames must never be Unicode-normalised: `Full‐Stack-Type‐Safety.md` contains U+2010 and `ScottyStack＋.md` contains U+FF0B, and transliterating either to ASCII produces a 404.
